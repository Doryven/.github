# Security policy

## Reporting a vulnerability

**Please do not open a public issue for a security problem.**

Report it privately through GitHub's advisory form on the affected repository:
**Security → Report a vulnerability**. If that is unavailable, email
**security@doryven.com** and we will confirm receipt.

Please include what you can: the affected repository and version, what an attacker
gains, and the smallest reliable way to reproduce it. A proof of concept helps more
than a scanner name.

## What to expect

| | |
|---|---|
| Acknowledgement | within 3 working days |
| Initial assessment | within 10 working days |
| Fix or documented mitigation | agreed with you, based on severity |

We will tell you plainly if we judge a report not to be a vulnerability, and why.

## Disclosure

We will credit you in the advisory unless you prefer otherwise. We ask that you give
us a reasonable window to ship a fix before publishing. We will not pursue anyone
acting in good faith under this policy.

## Scope

Doryven's software, and its deployment configuration in these repositories. Findings
in third-party dependencies should go to that project; tell us anyway if a Doryven
release is exposed by it.

There is no paid bug bounty.
