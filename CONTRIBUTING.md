# Contributing

Thanks for taking the time. These defaults apply to every Doryven repository that does
not publish its own guide.

## Before you write code

Open an issue first for anything beyond an obvious fix. It is cheaper to disagree about
an approach in a paragraph than in a pull request.

For security problems, do not open an issue at all — see [SECURITY.md](SECURITY.md).

## Pull requests

- One concern per pull request. A bug fix and a refactor are two pull requests.
- Explain **why**, not just what. The diff shows what changed; the description should
  say what problem it solves and what you considered instead.
- Include a test that fails without the change. If it cannot be tested, say why in the
  description rather than leaving it unsaid.
- Keep the existing style of the file you are editing over any personal preference.
- Run the repository's checks before pushing; each repository documents its own.

## Commit messages

A short imperative subject, then a body explaining the reasoning. Reference the issue
being closed. Commits are authored by their author — do not add co-author or
generated-by trailers for tooling.

## Licensing

By contributing you agree your work is released under the licence in that repository.
Do not paste code you did not write or are not licensed to contribute.
